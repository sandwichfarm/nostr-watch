**Step 1: Create `docs/.vitepress/packages.data.ts` (build-time data loader)**

This data loader reads all `package.json` files from apps/, libraries/, internal/ at build time and produces the package metadata for the discovery index.

```typescript
import { glob } from 'glob'
import { readFileSync } from 'fs'
import { resolve } from 'path'

export default {
  async load() {
    const root = resolve(__dirname, '../..')
    const manifests = glob.sync('{apps,libraries,internal}/*/package.json', {
      cwd: root,
      ignore: ['**/node_modules/**']
    })
    return manifests.map(p => {
      const pkg = JSON.parse(readFileSync(resolve(root, p), 'utf-8'))
      const type = p.split('/')[0]
      const slug = p.split('/')[1]
      return {
        name: pkg.name ?? slug,
        description: pkg.description ?? '',
        version: pkg.version ?? '',
        status: pkg.nostrwatch?.status ?? 'alpha',
        type,
        slug,
        deprecated: pkg.nostrwatch?.deprecated ?? false,
        link: `/${type}/${slug}/`,
      }
    }).sort((a, b) => a.name.localeCompare(b.name))
  }
}
```

Note: The `nostrwatch.status` and `nostrwatch.deprecated` fields may not exist in all package.json files yet. The loader defaults to `'alpha'` status and `false` deprecated — this is fine; packages can add metadata later.

For the three known deprecated packages (`apps/nocapd`, `internal/nwcache`, `libraries/schemata`), if `nostrwatch.deprecated` is not set, the component won't show them as deprecated initially. This is acceptable — the deprecation stubs in their READMEs will handle that messaging. The data loader can be updated when package.json metadata is added.

import { computed } from 'vue'
import { data as packages } from '../../packages.data'

const props = defineProps<{ type?: string }>()

const filtered = computed(() => {
  const list = props.type
    ? packages.filter(p => p.type === props.type)

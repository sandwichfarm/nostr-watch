   - `MonitorService`: active monitoring subscription management

   **Cache Adapters:**
   a. What cache adapters do — store and query relay data locally
   b. Base class: `CacheAdapter`
   c. Interface: `ICacheAdapter` with required methods:
      - `ready(): Promise<void>` — signal readiness
      - `REQ(filters: any[]): Promise<IEvent[]>` — query events
      - `COUNT(filters: any[]): Promise<number>` — count events
      - `DELETE(filters: any[]): Promise<string[]>` — delete events
      - `addEvent(event: IEvent): Promise<void>` — insert event
      - `addEvents(events: IEvent[]): Promise<void>` — batch insert
      - `putEvent(event: IEvent): Promise<void>` — upsert event
      - `DUMP(): Promise<IEvent[]>` — dump all events
   d. Registration: `r66.useAdapters({cache: MyCacheAdapter})`
   e. Existing cache adapters:
      - NostrSqliteAdapter — SQLite-backed local storage
      - NostrToolsAdapter — nostr-tools pool-backed remote cache

   **WebSocket Adapters:**
   a. What websocket adapters do — provide WebSocket connectivity to relays
   b. Registration: `r66.useAdapters({websocket: MyWsAdapter})`
   c. Existing websocket adapters:

   d. Link to `libraries/route66/adapters/` as reference implementations

7. **Known Limitations**: MUST include all three CONCERNS.md entries:

   - "**Hardcoded filter limit:** `MonitorService` caps subscriptions at 10 filters (`MAX_FILTERS = 10`) regardless of what the relay actually supports. Relays that allow more filters will not be fully utilized; relays that allow fewer may reject subscriptions silently. Split subscriptions across multiple `MonitorService` instances as a workaround. See [CONCERNS.md -- Hardcoded Filter Limits](../../.planning/codebase/CONCERNS.md#hardcoded-filter-limits)."

   - "**Default relays hardcoded in source:** Default relay URLs in `RelayService` are set in the constructor rather than loaded from configuration. Changing the default relay list requires a code change. Pass an explicit relay list to the constructor as a workaround. See [CONCERNS.md -- Default Relay Configuration](../../.planning/codebase/CONCERNS.md#default-relay-configuration)."

   - "**Incomplete RTT extraction:** RTT values are not extracted from chronicle period metadata. Uptime and downtime records may be incomplete. No workaround available at this time. See [CONCERNS.md -- Incomplete RTT Extraction](../../.planning/codebase/CONCERNS.md#incomplete-rtt-extraction)."
